The `builder` key has the following requirements and recommendations:
* Replicated recommends that you include only the minimum Helm values in the `builder` key required to template the Helm chart with the correct image tags.
* Use only static, or _hardcoded_, values in the `builder` key. You can't use template functions in the `builder` key because values in the `builder` key are not rendered in a customer environment.
* Any `required` Helm values that need to be set to render the chart templates must have a value in the `builder` key. For more information about the Helm `required` function, see [Using the 'required' function](https://helm.sh/docs/howto/charts_tips_and_tricks/#using-the-required-function) in the Helm documentation.
* Specify `kubeVersion` in the root Helm chart. The Vendor Portal renders Helm charts with the minimum Kubernetes minor version that satisfies the `kubeVersion` in the root Helm chart. For example, if the chart specifies `kubeVersion: >=1.24.1`, then it's rendered with Kubernetes 1.25.0. If this fails or if a `kubeVersion` is not specified in the root Helm chart, then the Vendor Portal attempts to render the chart with each supported minor version of Kubernetes up to the latest version.
* Every conditional template that uses a unique image must render with the values in the `builder` key. If a template is gated on a value (for example, a self-signed certificate Job that renders only when `tls.mode` is `self-signed`), set that value in the `builder` key so that the template renders and its image is included.
* The Vendor Portal renders the chart once, using only the chart's default values and the values in the `builder` key. The `values` and `optionalValues` keys are not used to build the image list, so a value set only in `values` does not cause a conditional template to render.
* If two templates are mutually exclusive, such as the two branches of an `if`/`else` on the same value, they can't both render in a single pass. Set the `builder` key to render one branch, and list the images from the other branch in the `additionalImages` field of the Application custom resource. For more information, see [Define additional images](/vendor/operator-defining-additional-images).
* If an image isn't rendered with the `builder` values and isn't listed in `additionalImages`, it is left out of the release's image list. The release still builds successfully and no warning is shown. The missing image causes a failure only when a customer who installs in an air-gapped environment, or who pushes images to their own registry, enables the feature that uses that image.
