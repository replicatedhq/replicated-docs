Specifies additional flags to pass to the `helm upgrade` command.
The Replicated installer runs `helm upgrade` for _all_ deployments, not just upgrades, by specifying the `--install` flag.

The Replicated installer passes these flags in addition to the flags it passes by default.
The values specified in this field take precedence if the installer already passes the same flag.

Template functions can parse the `helmUpgradeFlags` attribute.
For more information, see [About Replicated template functions](/reference/template-functions-about).

For non-boolean flags that require an additional argument, such as `--timeout 1200s`, you must use an equal sign (`=`) or specify the additional argument separately in the array.

:::note
KOTS does not pass `--wait` to Helm by default. KOTS installs charts in the order set by [`weight`](#weight), and starts the next chart as soon as Helm returns for the previous one, without waiting for its resources to be ready. If a chart depends on resources from an earlier chart being ready (for example, an operator that must be running before a later chart creates its custom resources), add `--wait` to the `helmUpgradeFlags` of the earlier chart. If the later chart also depends on Jobs in the earlier chart completing, add `--wait-for-jobs` as well.

With `--wait`, Helm waits for all non-hook resources to be ready before it runs post-install or post-upgrade hooks. Do not add `--wait` to a chart where a non-hook resource depends on a resource created by a hook (for example, a Deployment with an init container that waits for a database custom resource created by a post-install hook). This creates a deadlock where the install times out.
:::

#### Examples

```yaml
helmUpgradeFlags:
  - --timeout
  - 1200s
  - --history-max=15
```

Wait for the chart's resources to be ready and its Jobs to complete before the next chart installs:

```yaml
helmUpgradeFlags:
  - --wait
  - --wait-for-jobs
```
