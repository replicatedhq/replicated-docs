This section lists the ports used by Embedded Cluster. These ports must be open and available for both single- and multi-node installations.

#### Ports used by local processes

The following ports must be open and available for use by local processes running on the same node. It is not necessary to create firewall openings for these ports.

* 2379/TCP
* 7443/TCP
* 9099/TCP
* 10248/TCP
* 10257/TCP
* 10259/TCP

#### Ports required for bidirectional communication between nodes

The following ports are used for bidirectional communication between nodes.

For multi-node installations, create firewall openings between nodes for these ports.

For single-node installations, ensure that there are no other processes using these ports. Although there is no communication between nodes in single-node installations, these ports are still required.

* 2380/TCP
* 4789/UDP
* 6443/TCP
* 9091/TCP
* 9443/TCP
* 10249/TCP
* 10250/TCP
* 10256/TCP

#### Embedded Cluster console and API port

The Embedded Cluster daemon serves the admin console and its HTTP API on port 30000/TCP on every node. Users open the admin console in a browser on this port. Nodes use it to join the cluster and to receive streamed upgrades, and external automation uses it for headless installs and programmatic node joins.

Create a firewall opening for port 30000/TCP so that users can reach the admin console. For multi-node installations, also open this port between nodes.

If port 30000 is occupied, you can select a different port with `--api-port` during installation. The port cannot be changed after installation. For more information, see [install](/embedded-cluster/v3/embedded-cluster-install) and [Embedded Cluster API](/embedded-cluster/v3/embedded-cluster-external-api).

In Embedded Cluster versions earlier than 3.17.0-beta.1, the installer UI and admin console use port 30080/TCP and the API uses port 30081/TCP. When you upgrade a cluster that uses the default ports to 3.17.0-beta.1 or later, the console and API move to port 30000, so open port 30000/TCP before you upgrade. A cluster installed with a custom `--api-port` keeps that port for both the console and the API.
