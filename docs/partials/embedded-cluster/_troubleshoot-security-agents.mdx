#### Symptom {#security-agents-symptom}

Symptoms can include:

* The kube-proxy or calico-node pods restart repeatedly.

* Pod logs contain I/O timeouts when connecting to the Kubernetes API service IP address. This is the first address in the service CIDR, which is `10.244.128.1` by default.

* Embedded Cluster binaries or systemd units are missing or fail to run.

* Containers fail to restart.

These symptoms often appear during a new installation, or after a security tool restarts, receives a policy update, or the host reboots.

#### Cause {#security-agents-cause}

A security tool on the host is blocking or removing firewall rules, binaries, or files that Kubernetes needs to run. This includes firewall management, endpoint protection, and application control tools.

#### Solution {#security-agents-solution}

Work with the security team to update the tool's policy so that it allows what Kubernetes needs to run. For more information about the requirements, see [Security tools on the host](installing-embedded-requirements#security-agents) in _Embedded Cluster installation requirements_.

Updating the tool's policy does not undo changes that the tool already made. You might also need to reboot the host to reset the firewall and restore any kernel parameters that the tool changed. In some cases, you also need to remove `ebtables` rules that the tool added.
