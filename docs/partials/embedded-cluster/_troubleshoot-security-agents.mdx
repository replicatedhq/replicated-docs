#### Symptom

Symptoms can include:

* The kube-proxy or calico-node pods restart repeatedly.

* Pod logs contain I/O timeouts when connecting to the Kubernetes API service IP address, which is `10.244.128.1:443` by default.

* Embedded Cluster binaries or systemd units are missing or fail to run.

* Containers fail to restart.

These symptoms often appear during a new installation, or after a security tool restarts, receives a policy update, or the host reboots.

#### Cause

A security tool on the host is blocking or removing firewall rules, binaries, or files that Embedded Cluster needs. This includes firewall management, endpoint protection, and application control tools.

#### Solution

Work with the security team to update the tool's policy so that it allows what Embedded Cluster needs. For the requirements and why each one matters, see [Security tools on the host](installing-embedded-requirements#security-agents) in _Embedded Cluster installation requirements_.

Update the policy rather than disabling or removing the tool. Disabling or removing a tool does not undo changes that it already made. You usually still need to reboot the host to reset the firewall and restore any kernel parameters that the tool changed. In some cases, you also need to remove `ebtables` rules that the tool added.
