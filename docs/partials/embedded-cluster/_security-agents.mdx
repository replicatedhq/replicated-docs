Embedded Cluster can run on hosts that also run endpoint security, firewall management, and application control tools, such as Illumio VEN or CrowdStrike Falcon. Disabling these tools is a request that many security teams will not approve. Instead, the following table lists the narrower exceptions that Embedded Cluster needs, along with why each one matters. Configuration steps vary by product and version, so work with the tool's vendor to apply them.

| Requirement | Why |
|---|---|
| Do not block, flush, replace, or reorder the `KUBE-*` and `cali-*` firewall rules, whether the host uses `iptables` or `nftables`. The usual approach is to exclude cluster nodes from the tool's host firewall management, or to use the tool's Kubernetes mode if it has one. | The cluster's networking components, kube-proxy and Calico, route all pod and service traffic through these rules. If a tool blocks the rules during installation, kube-proxy restarts repeatedly and the installation does not complete. If a tool removes the rules later, such as after the tool restarts, receives a policy update, or the host reboots, pods can no longer reach the Kubernetes API and the application stops working. |
| Allow traffic to and from the pod and service networks, and on the `cali*` and `vxlan.calico` network interfaces. For the list of interfaces and networks, see [About firewalld configuration](#about-firewalld-configuration). | All traffic between pods, services, and the host uses these networks and interfaces. A default-deny policy drops this traffic, with the same result as removing the firewall rules. |
| Allow binaries to run from the paths listed in [Executable paths](#executable-paths). | Embedded Cluster runs Kubernetes and its networking components from these paths. If a tool blocks execution, installation or upgrade fails, or the node cannot start the cluster. |
| Do not quarantine or remove files that Embedded Cluster installs. Exclude `DATA_DIR/k0s/containerd` from file scanning, where `DATA_DIR` is the Embedded Cluster data directory. | Removing a cluster binary, a systemd unit, or a networking binary stops the node. Scanners that hold files open in container filesystems can also prevent containers from restarting. |
| Do not change the kernel modules and parameters that Embedded Cluster configures. For the list, see [Host configuration](#host-configuration). | Hardening tools that reset values such as `net.ipv4.ip_forward` or `net.ipv4.conf.all.rp_filter` drop pod traffic, even when no firewall rule changed. |
