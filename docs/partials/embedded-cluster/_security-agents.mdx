Endpoint security, firewall management, and application control tools, such as Illumio VEN or CrowdStrike Falcon, can interfere with Embedded Cluster. Replicated recommends disabling these tools on Embedded Cluster hosts. If disabling a tool is not an option in the installation environment, configure the tool to meet the requirements in the following table. Each requirement includes the reason that Embedded Cluster needs it. Configuration steps vary by product and version, so work with the tool's vendor to apply them.

| Requirement | Why |
|---|---|
| Do not block, flush, replace, or reorder the `KUBE-*` and `cali-*` firewall rules, whether the host uses `iptables` or `nftables`. The usual approach is to exclude cluster nodes from the tool's host firewall management, or to use the tool's Kubernetes mode if it has one. | The cluster's networking components, kube-proxy and Calico, route all pod and service traffic through these rules. If a tool blocks the rules during installation, kube-proxy restarts repeatedly and the installation does not complete. If a tool removes the rules later, such as after the tool restarts, receives a policy update, or the host reboots, pods can no longer reach the Kubernetes API and the application stops working. |
| Allow traffic to and from the pod and service networks, and on the `cali*` and `vxlan.calico` network interfaces. For more information about the interfaces and networks, see [About firewalld configuration](#about-firewalld-configuration) in this document. | All traffic between pods, services, and the host uses these networks and interfaces. A default-deny policy drops this traffic, with the same result as removing the firewall rules. |
| Allow binaries to run from the Embedded Cluster executable paths. For more information about the paths, see [Executable paths](#executable-paths) in this document. | Embedded Cluster runs Kubernetes and its networking components from these paths. If a tool blocks execution, installation or upgrade fails, or the node cannot start the cluster. |
| Do not quarantine or remove files in the Embedded Cluster executable paths or data directory. For more information, see [Executable paths](#executable-paths) and [Data directory contents](#data-directory-contents) in this document. If the tool scans files, also exclude `DATA_DIR/k0s/containerd` from scanning, where `DATA_DIR` is the Embedded Cluster data directory. | Removing a cluster binary, a systemd unit, or a networking binary stops the node. Scanners that hold files open in container filesystems can also prevent containers from restarting. |
| Do not change the kernel modules and parameters that Embedded Cluster configures. For more information about the kernel modules and parameters, see [Host configuration](#host-configuration) in this document. | Hardening tools that reset values such as `net.ipv4.ip_forward` or `net.ipv4.conf.all.rp_filter` drop pod traffic, even when no firewall rule changed. |
