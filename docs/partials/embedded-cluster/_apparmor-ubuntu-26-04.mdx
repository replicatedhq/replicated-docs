On Ubuntu 26.04 hosts with recent kernels, such as `7.0.0-43-generic` and `7.0.0-1017-aws`, AppArmor denies signals between processes in the same container. Applications that rely on these signals can stop responding or fail to shut down. For example, PostgreSQL pods can hang until the database reaches its connection limit. The kernel log on the host shows `apparmor="DENIED" operation="signal"` entries with a `peer` that ends in `//&unconfined`.

The cause is a bug in the default AppArmor profile in containerd, which Embedded Cluster uses to run containers. For more information, see [containerd issue #14485](https://github.com/containerd/containerd/issues/14485) in GitHub. The fix applies to the following Embedded Cluster versions:

* **Kubernetes 1.35 and earlier:** These versions use containerd 1.7, which is end of life and does not receive the fix. To run these versions, use Ubuntu 24.04 hosts.
* **Kubernetes 1.36 and later:** These versions use containerd 2.3. The fix will be available in a future Embedded Cluster release after it is available in containerd and k0s.

Until a release with the fix is available, use Ubuntu 24.04 hosts, or keep Ubuntu 26.04 hosts on an earlier kernel, such as `7.0.0-38-generic`.
