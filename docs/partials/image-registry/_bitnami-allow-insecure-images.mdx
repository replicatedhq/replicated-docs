Some third-party charts, such as Bitnami charts, check that each image comes from the chart's original registry and repository. If you rewrite an image to the Replicated proxy registry or to a local or customer-managed registry, the chart fails to render with an error that includes "Original containers have been substituted for unrecognized ones." Some chart versions also fail if you change only the repository, such as to `docker.io/bitnamilegacy/postgresql`. These checks are part of the chart, not Replicated, and they can change between chart versions.

:::important
Set the following value in the chart's `values.yaml` file or in the HelmChart custom resource `builder` key. If you set it only in the HelmChart `values` or `optionalValues` key, the air gap bundle build can fail, because the build renders the chart with only the chart's default values and the `builder` key.
:::

To skip the check, add the following to the chart's `values.yaml` file. Use this nested form. Helm ignores a single dotted key such as `global.security.allowInsecureImages: true`.

```yaml
global:
  security:
    allowInsecureImages: true
```

Despite its name, this setting only skips the chart's image check. It does not change how images are pulled.
