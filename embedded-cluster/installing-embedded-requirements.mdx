# Embedded Cluster installation requirements (Beta)

This topic lists the installation requirements for Replicated Embedded Cluster. Ensure that the installation environment meets these requirements before you attempt to install.

## System requirements

<EmbeddedClusterRequirements/>

## Disk space requirements {#disk-space}

The filesystem that contains the data directory requires the most disk space. The data directory holds the k0s Kubernetes data, including etcd and containerd images, along with the OpenEBS PersistentVolume data and Embedded Cluster assets such as charts and binaries. By default, the data directory is `/var/lib/APP_SLUG`, where `APP_SLUG` is the unique slug of the application.

During installation, the host preflight checks enforce the following disk space requirements. The installation is blocked when these requirements are not met:

<table>
  <tr>
    <th>Location</th>
    <th>Requirement</th>
  </tr>
  <tr>
    <td>The filesystem containing the data directory</td>
    <td>40Gi or more of total space, and less than 80% used</td>
  </tr>
  <tr>
    <td>The filesystem containing the data directory (air gap installations, joining nodes only)</td>
    <td>Available space of at least 2x the size of the air gap images archive. This applies to both controller and worker nodes.</td>
  </tr>
</table>

After installation, the host support bundle includes additional disk space checks. These checks do not block anything, but they are reported as failed when the requirement is not met. They cover the root filesystem (`/`) with 40Gi of total space, less than 80% used, and 10Gi available; the filesystems containing the data directory and the k0s data directory; and `/tmp` with 5Gi of total space.

### Custom partitioning {#custom-partitioning}

If the root filesystem (`/`) has limited space, place the data directory on a separate disk or partition:

* Create a dedicated filesystem and mount it at the data directory path, or pass the `--data-dir` flag with the Embedded Cluster `install` command to relocate the data directory. The relocated data directory must meet the same disk space and write latency requirements as the default location. For more information, see [install](/embedded-cluster/v3/embedded-cluster-install).

:::warning
Do not create a symbolic link from the data directory path to another location. A host preflight check blocks the installation when the data directory is a symlink.
:::

When you use separate partitions, each partition cannot share free space with the others, so plan for the following:

* **Data directory mount**: Enough space for etcd, container images, PersistentVolumes, and backups. The enforced minimum is 40Gi with less than 80% used, but plan for steady-state growth above that minimum. Upgrades also stage the new k0s binary in the `bin` subdirectory of the data directory, which temporarily requires several hundred MB alongside the existing binary during the upgrade.
* **Root filesystem**: At least 10Gi of available space. Log files written under `/var/log` also consume root filesystem space.
* **`/tmp`**: At least 5Gi of total space.

Because separate partitions cannot share free space, the aggregate total storage for a host with custom partitioning should be larger than the total for a host that uses a single root volume.

## Unix accounts for Kubernetes components

During installation, Embedded Cluster automatically creates the following Unix accounts, which internal Kubernetes components require:

* **etcd**: Used by the Kubernetes etcd database, which stores cluster state.
* **konnectivity-server**: Used by the Konnectivity service, which facilitates secure communication between internal components.
* **kube-apiserver**: Used by the Kubernetes API server.
* **kube-scheduler**: Used by the Kubernetes scheduler to schedule workloads such as pods.

You do not need to take any action to create these roles. Removing them will make the cluster non-functional.

For more information about the internal Kubernetes components, see [Kubernetes Components](https://kubernetes.io/docs/concepts/overview/components/) in the Kubernetes documentation.

For more information about the Konnectivity service, see [Set up Konnectivity service](https://kubernetes.io/docs/tasks/extend-kubernetes/setup-konnectivity/) in the Kubernetes documentation.

:::note
Embedded Cluster v3 disables the `update-prober` feature, which checks `updates.k0sproject.io` for updates, on every node that it installs or joins, so these nodes do not call `updates.k0sproject.io`. In installations upgraded from Embedded Cluster v2, nodes that existed before the upgrade keep their v2 setting, and might call `updates.k0sproject.io` approximately every 30 minutes. Embedded Cluster does not use the `update-prober` feature, and blocking these calls in your firewall does not affect Replicated product functionality.
:::

## About firewalld configuration

When Firewalld runs in the installation environment, Embedded Cluster modifies the Firewalld config to allow traffic over the pod and service networks. It also opens ports 2380, 6443, 9443, and 10250/TCP and port 4789/UDP. Embedded Cluster does not open the console and API port (30000/TCP by default) or ports 9091, 10249, and 10256/TCP. Create firewall openings for those ports yourself. See [Port requirements](#port-requirements).

Embedded Cluster adds the following rule to Firewalld:

```xml
<?xml version="1.0" encoding="utf-8"?>
<zone target="ACCEPT">
  <interface name="cali+"/>
  <interface name="tunl+"/>
  <interface name="vxlan-v6.calico"/>
  <interface name="vxlan.calico"/>
  <interface name="wg-v6.cali"/>
  <interface name="wireguard.cali"/>
  <source address="[pod-network-cidr]"/>
  <source address="[service-network-cidr]"/>
</zone>
```
