# Application status (Beta)

This topic describes the application status that end users see in Embedded Cluster 3.13.0-beta.1 and later, and what your release needs for it to display.

## Overview

Embedded Cluster displays an **Application status** card that shows whether the application is ready to use, not only whether the install or upgrade finished. The card appears in the following places:

* The finish screen at the end of an install or upgrade in the wizard.
* The dashboard of the persistent admin console, if the end user installed it. For more information, see [Persistent admin console](embedded-persistent-console).

The card reads application status from the Replicated SDK running in the cluster. It refreshes every ten seconds and keeps refreshing while the screen is open, so the dashboard also shows a healthy application that later becomes unhealthy. Because the status comes from inside the cluster, it works in air gap installations.

## Requirements

The card displays only when your release includes the Replicated SDK. If the SDK is not installed, Embedded Cluster hides the card rather than show an empty status.

The SDK automatically reports on the resources in the Helm release that contains it, including its subcharts. If your application uses more than one Helm release, the SDK reports on resources in the other releases only if you list them in its `statusInformers` value. For more information, see [Enable and understand application status](/vendor/insights-app-status).

## What the card shows

The card shows the aggregate application status, a count of ready components (for example, `12 of 14 components ready`), and a list of the components that are not ready, with the least healthy first. End users can expand the list to show every component.

The status labels are Ready, Updating, Degraded, Unavailable, and Missing. These are the same statuses that the Vendor Portal and the KOTS Admin Console display.

The card also uses the following states:

* Checking application health: The SDK has not finished computing status yet.
* Unknown: The SDK is running but has no resources to report on. The card does not show Ready in this case, because the SDK had nothing to check. The card displays "The application did not provide resources to verify."
* Unable to check application health: Embedded Cluster could not reach the SDK.

On the finish screen, the completion message reflects the status. When the application is ready, the message says that it is ready to use. Until then, the message says that the application is waiting to become ready, and the card warns that application links might not work yet. During an install or upgrade, Missing displays as "Waiting for application resources," because Kubernetes might not have created every resource yet.
